# Idea Scoring Framework

## Guidelines (read before scoring — do NOT copy these into the output)

### Challenge question rationale
- **"30 seconds"** — Judges see 20+ demos. If yours needs explanation, you lose.
- **"One-sentence pitch"** — Forces clarity. PolicyGuard: "The compliance API for AI agents." Clear.
- **"Wrapper or agent?"** — Wrappers that just call an API don't score on autonomy (often 20%).
- **"Sponsor prizes"** — Forced integrations are obvious to judges. Natural fits win.
- **"Wow moment in 60s"** — The demo is 3 min. Wow must hit in the first 60s.
- **"API is down"** — Winners had DEMO_MODE=true. Live-only = broken demo.
- **"Achievable?"** — Cut 40% of what you think you can build. Core loop at halfway or cut features.

### Winning idea patterns
1. **Close a loop competitors leave open.** "Every GEO tool monitors. We act and measure."
2. **Frame as infrastructure, not app.** "The compliance API for the agentic web" > "A tool."
3. **Ride accelerating trend.** AI agents without compliance, brands misrepresented by AI.
4. **One trigger, full autonomy.** User clicks ONE button. Everything else is autonomous.

### Sponsor optimization
- Natural fit = product genuinely needs the tool
- Visible = judges SEE the tool working during demo
- Specific criteria = meets the sponsor's exact prize requirements (read carefully!)

## Challenge questions (ask EVERY one)

1. "Can a judge understand this in 30 seconds?"
2. "What's the one-sentence pitch?"
3. "Is this a wrapper or does it make autonomous decisions?"
4. "Which sponsor prizes does this NATURALLY target?"
5. "Can you demo the wow moment in under 60 seconds?"
6. "What happens when the API is down during your live demo?"
7. "Is this achievable in the build window? Be honest — cut 40%."
